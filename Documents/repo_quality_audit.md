# Repo Quality Audit

## Scope

This audit checks the current `SRSC - work` repository for consistency with the
global and repo-specific `AGENTS.md` guidance, with emphasis on professionalism,
reproducibility, and whether the codebase reads like maintained research
software rather than a collection of local experiments.

## Current strengths

1. The main pipeline logic is modular and organized around explicit entrypoints in `src/run_pipeline.py`, `src/config.py`, `src/omix_io.py`, `src/linkage_audit.py`, and the attribution and rejuvenation helpers.
2. Raw inputs under `data/RAW` are treated as immutable in the active workflow, and derived outputs are written into `results` and `figures`.
3. Linkage-sensitive and attribution-sensitive outputs are guarded by explicit estimability logic instead of silent fallbacks.
4. Key interpretation-facing result tables follow a standard machine-readable schema with `available`, `estimable`, `reason`, `n_used`, `method`, `ci_low`, `ci_high`, and `evidence_level`.
5. The documentation around study design, group-label translation, and `OMIX007582` mapping limits is more explicit than in many exploratory bioinformatics repos and generally reads as human-curated rather than autogenerated.

## Issues found and addressed

1. Repo hygiene was incomplete. Local caches, logs, generated outputs, and editor state were not fully ignored, which made the repo structure look noisier and less intentional than it should.
2. Several orphaned helper files were clearly non-canonical:
   - `src/demo.py`
   - `src/scripts/demo.R`
   - `src/scripts/Metadata_9283.PY`
   These files contained hard-coded local paths, duplicated snippets, or trivial throwaway code.
3. `CITATION.cff` contained mojibake in the author name and used a title that no longer matched the current repository positioning.
4. `Documents/PLAN.md` had drifted into a more conversational, provisional tone and also contained encoding artifacts.
5. `src/preprocessing.py` still used `print()` for a runtime warning in pipeline code instead of the shared logger.
6. `src/config.py` still contained internal phrasing such as "or whatever you implemented," which reads as draft language rather than maintained software documentation.

## Fixes applied

1. Expanded `.gitignore` to cover generated outputs, local caches, logs, and local-only provenance files.
2. Removed non-canonical debug/demo files and replaced the `OMIX009283` helper with a proper documented CLI module, `src/omix009283_metadata.py`.
3. Normalized `CITATION.cff` encoding and aligned its title with the current repo identity.
4. Rewrote `Documents/PLAN.md` into a professional implementation-facing plan.
5. Added this audit note as a maintained repo-quality checkpoint.
6. Replaced the remaining `print()` warning in `src/preprocessing.py` with structured logging.
7. Tightened wording and defaults in `src/config.py` so the code comments and configuration surface read less like internal drafts.

## Remaining residual issues

1. `src/scripts/process_OMIX007582_Mammal40.R` is now parameterized and path-agnostic. Its help/CLI path and one-prefix IDAT rebuild are smoke-tested from the main `srsc` environment, but full Mammal40 rebuilding remains outside Python CI because it requires the sesame Bioconductor stack and large IDAT inputs.
2. The `Documents/study_sections/` and PDF-extraction artifacts are reference materials, not polished public documentation. That is acceptable, but they should be treated as supporting evidence files rather than part of the primary narrative surface.
3. The methylation sample-map limitation remains scientific rather than stylistic: `OMIX007582` still lacks a defensible biological sample map in the public files bundled here.

## Overall assessment

The repo now presents as a credible human-maintained computational biology project rather than an obviously AI-shaped or purely exploratory workspace. The remaining gaps are concentrated in a small number of secondary support scripts and in the underlying public-data limitations, not in the core pipeline design.
